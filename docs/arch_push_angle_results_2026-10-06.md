# 아치 타깃 PUSH 후 link6 각도 오차 측정 (2026-10-06)

Gazebo HIL(가상 터널 + 플랫폼)에서 `coverage_planner_node`(`hil:=true`)가 타깃을 주고, 실물 Piper가 `piper_controller_node`(이날 추가한 IK 다듬기 포함)로 이동한 뒤 `push_forward_node`로 PUSH까지 마친 상태에서 잰 값이다.

## 측정 방법

- **각도 기준점**: 아치 원 중심, world (Y, Z) = (0, 3.0) (`tunnel_geometry.ARCH_CENTER_*`).
- **θ**: 중심에서 +Y 수평 방향을 0°로 천장 쪽으로 잰다. 0° = +Y 벽 꼭대기, 90° = 천장, 180° = −Y 벽 꼭대기. 타깃 i의 θ = i × 180°/42 (4.2857° 간격, 43개).
- **오차** = link6 θ − 타깃 θ. 90° 미만에서 −, 90° 초과에서 +면 link6가 목표보다 바닥 쪽(아래)에 있다는 뜻.
- **실물 팔**: `/joint_states`(실물 관절각)를 IK 모델 FK로 link6 위치로 바꾸고, 플랫폼 위치(`/sim/tf` world→base_link)를 더한 값.
- **RViz/Gazebo**: `/sim/tf`의 world→link6. PUSH 후에는 Gazebo 팔이 가상 벽에 막혀 실물 자세를 다 못 따라가므로 **실물 팔 값이 실제 결과**다(RViz 값은 참고용).
- 3초 동안 약 350회 평균. 그 3초 동안 실물 θ가 0.001° 넘게 움직이면 팔이 아직 자리 잡는 중으로 보고 다시 쟀다(모든 값은 흔들림 0 상태).
- **타깃 선택(15° 간격)**: 30°의 배수는 정확히 맞는 타깃(0, 7, 14, 21, 28, 35, 42), 그 사이 15° 지점은 두 타깃의 정중앙(±2.14°)이라 90° 기준 좌우 대칭이 되게 3, 10, 17 / 25, 32, 39를 골랐다. 13개 × 계산기(`arch_target_solver`) 3세트 = 39회.

## 측정 중 기록해 둘 점

- 계산기 표의 17번·25번 3세트는 손목 특이점(j5 ≈ 0°) 해였지만, 컨트롤러를 켜둔 채 2세트에서 넘어가면 직전 자세에서 이어 풀어서 특이점은 피하는 대신 j3 ≈ −162°(한계 −170°까지 약 8°)로 팔꿈치가 많이 접힌 자세로 갔다.
- 14번·28번 2세트는 표 자체가 손목이 약간 비틀린 해라, 실물도 j1/j4/j6가 표와 3~5° 다르고 X 오차가 2~3.5mm로 다른 세트(~1mm)보다 컸다(θ 오차에는 영향 거의 없음).
- PUSH 깊이(아치 중심에서 link6까지 거리)는 3.955~4.000m로 세트마다 달랐다(6cm standoff 목표 = 3.940m).
- 플랫폼 입력 실수(7번 2세트에 Z 4.45, 21번 3세트에 Y −0.10)는 TF로 확인해서 다시 잰 값만 남겼다.
